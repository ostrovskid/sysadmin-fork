# Транскрипт сессии Claude Code: как отличить голос человека

Знание нужно всему, что **принимает решения по репликам человека**: замки, гейты,
разборы сессий. Ошибка здесь — не косметика, а дыра в безопасности: если считать
голосом человека всё подряд, фраза подтверждения, лежащая **в файле или в выводе
команды**, откроет замок красной зоны (конституция C.11, prompt injection).

## Где лежит

`~/.claude/projects/<slug>/<session-id>.jsonl`, где `<slug>` — рабочий каталог с заменой
на `-` всех символов, кроме латинских букв и цифр (подробнее — «Какая сессия «своя»»). Формат — JSON Lines, одна запись на строку.

## Что выглядит репликой человека, но ею не является

Под `"type": "user"` движок кладёт **не только** то, что человек напечатал. Проверено
чтением настоящего файла: там же оказываются тексты загруженных скиллов (в разбираемой
сессии — 3600 строк скилла `update-config`), служебные caveat-блоки, вывод слэш-команд,
реплики субагентов.

Различители (проверены на реальных записях, не на догадке):

| Признак записи | Что это | Считать голосом человека? |
|---|---|---|
| `isMeta: true` | вставка движка: текст скилла, caveat-блок | нет |
| `sourceToolUseID` | контент, порождённый вызовом инструмента | нет |
| `isSidechain: true` | реплика внутри субагента | нет |
| `content` содержит блок `tool_result` | вывод инструмента | нет |
| текст начинается с `<command-name>`, `<local-command-`, `<system-reminder>`, `Base directory for this skill` | служебная обёртка | нет |
| ничего из перечисленного, `message.role: "user"` | напечатал человек | **да** |

У настоящих реплик человека в наблюдаемом формате присутствовало поле `promptSource`,
а `isMeta` отсутствовало — но опираться лучше на **отсекающие** признаки выше: они
проверены, а состав полей движок может менять от версии к версии (наблюдалась 2.1.218).

Сообщение другой сессии (межсессионная переписка) тоже лежит под `"type": "user"`, но с
`isMeta: true` и `origin.kind: "peer"`; реплика человека в новом формате — `origin.kind:
"human"` (сверено 28.09 и 02.10.2026).

## Какая сессия «своя»

Код, которому надо отличить **свою** сессию от чужой (разбор сессий, поиск журнала по номеру),
опирается на три факта, проверенных 02.10.2026 и повторно 27.10.2026 (Windows, запуск из VS Code,
Claude Code 2.1.310 при повторе; CLI, macOS и Linux не проверялись):

- **Номер сессии — в среде:** `CLAUDE_CODE_SESSION_ID` = имя файла журнала. Но **субагент**
  (Agent tool, агенты workflow) получает номер **родителя** и его же путь scratchpad — замер
  прямо в субагенте, повторён 27.10.2026 на 2.1.310. Переменных с именами `CLAUDE_CODE_PARENT*` /
  `CLAUDE_CODE_AGENT*` в его среде нет, а `CLAUDE_CODE_CHILD_SESSION=1` стоит и в основной сессии
  (наблюдалось при запуске из VS Code) — по ним субагента не отличить. Журналы субагентов лежат
  глубже — `<slug>/<session-id>/subagents/…` — и под шаблон `*/*.jsonl` не попадают.
- **`<slug>` собирается с потерями:** заменяется всё, кроме латинских букв и цифр, — кириллица
  тоже, по дефису на букву (наблюдалось 27.10.2026: папки журналов из одних дефисов). Поэтому
  `my_app`, `my app` и `my-app`, как и два русских имени одной длины, получат одно имя папки —
  вывод из правила, сами совпадения не наблюдались. По имени папки «где открыта сессия» не узнать.
- **Где открыта сессия — поле `cwd`** в записях журнала. Брать **первую** запись с `cwd`:
  внутри сессии он может смениться (наблюдалось: на подпапку рабочего каталога), а на Windows
  буква диска пишется то строчной, то заглавной — сравнивать после `normcase`/`normpath`.

Отсюда правило: номер сессии из среды или аргумента признавать своим, только если `cwd` первой
записи его журнала равен твоему корню; исключать из выборки **этот файл журнала**, а не все
журналы с тем же номером. В субагенте номер из среды без такой сверки укажет на сессию родителя.
Условие необходимое, но не достаточное: при нескольких сессиях, открытых в одном каталоге, оно
выполнится у всех.

## Как этим пользоваться

- Разрешающее решение (открыть замок) — только по записи, прошедшей **все** отсечки.
- Реплики агента (`type: "assistant"`) разрешением быть не могут в принципе: агент пишет
  их сам, значит мог бы выдать себе право.
- Ограничение свежести: подтверждение имеет смысл считать действительным несколько
  последних реплик человека, а не всю сессию.

## Грабля, которой куплено знание

24 теста замка на **самодельных фикстурах** дали 100% зелени при дыре в модели данных:
фикстуры воспроизводили представление агента о формате, а не сам формат. Дыра стала
видна только на прогоне по настоящему `.jsonl`. Отсюда правило: **парсер чужого формата
объявляется рабочим лишь после прогона на настоящем сырье** (сессия 2026-07-24, F2).
